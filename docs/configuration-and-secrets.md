# Configuration and secrets

Non-sensitive settings use environment variables. Credentials, connection strings, API tokens, session signing material, and Google service-account JSON are files under `SECRETS_DIR` and are mounted at `/run/secrets`. They must not be placed in Compose environment values, image layers, command arguments, shell tracing, CI artifacts, or logs.

Required files are `postgres_password`, `app_database_password`, `prefect_database_password`, `session_secret`, `app_database_dsn`, `legacy_database_dsn`, `prefect_database_dsn`, `prefect_api_auth`, `redis_url`, `redis_acl`, `nocodb_token`, `google_service_account.json`, and `sqlserver_connection_string`. The application DSN, legacy DSN, and Prefect DSN must use their matching dedicated roles and databases; `legacy_database_dsn` is read-only compatibility access for the legacy source. Set `SECRETS_GID` to a dedicated host group, assign every file to that group, use mode `0640`, and restrict the directory to the deployment account. Docker Compose bind-mounts file-backed secrets without changing their ownership or mode, so the application and Redis containers receive `SECRETS_GID` as a supplementary group. `prefect_api_auth` contains a randomly generated `username:password` value. Enable the same value on the Prefect server and clients, and protect its endpoint with Cloudflare Access. `redis_acl` defines a password-protected application user and a no-password `health` user restricted to `PING`; `redis_url` contains the matching application-user credential.

Non-sensitive integration selectors are configurable with `NOCODB_EMPLOYEE_TABLE_ID`, `GOOGLE_IOT_SPREADSHEET_ID`, `GOOGLE_IOT_SHEET_NAME`, `TIMESHEET_WEEKDAY_ACTIVITY`, `TIMESHEET_WEEKEND_ACTIVITY`, `TIMESHEET_IOT_ACTIVITY`, and `TIMESHEET_DEFAULT_PROJECT`; `.env.example` shows the v1-compatible defaults. Application containers also attach to the externally managed `digital-bast-network` so the legacy DSN can resolve its legacy PostgreSQL hostname.

Rotate one credential at a time: create the replacement at the provider, write it atomically to the secret store, redeploy the inactive slot, verify shadow traffic, switch, then revoke the old credential. Database credentials require coordinated role creation and DSN rotation before old-role removal. Record owner, time, scope, and validation outcome without recording secret values.

If a credential entered Git history, revoke it first. Freeze pushes, identify every affected ref, make an offline mirror backup, use `git filter-repo --sensitive-data-removal` to purge the exact file or value, force-push all rewritten refs, expire local reflogs and garbage-collect clones, invalidate CI caches and artifacts, and require every contributor to re-clone. Coordinate this disruptive operation with repository administrators.
